# Cross-Repository Contract

The Astro Survey Atlas organization contains three independent repositories.
They share versioned data contracts and stable URLs, not source-tree imports or
local filesystem paths.

| Producer/consumer | Contract | Warehouse responsibility |
| --- | --- | --- |
| Assets -> Warehouse | `ScanPlan` v2 through `ScanRequest`; `MocDiscoveryRequest` for bounded discovery | Validate, execute asynchronously, publish current `ast_*` state and evidence |
| Warehouse -> Assets | `ast_layer_index_v1`, `ast_file_index_v1`, `ast_coverage_index_v1`; evidence summary | Keep mappings strict, expose only ACTIVE layers, preserve order/precision and hashes |
| Workspace -> Warehouse | User-selected remote scan intent and credential references | Execute only the declared finite plan; never read credential values in reconcile |
| Assets -> Workspace | Reviewed Resource Package/MOC release and provenance | Not owned or generated by Warehouse |

## Compatibility Rules

- ScanPlan version `2` is the only accepted persisted scan plan in v1.
- The three `ast_*_v1` names version mappings and fields, not execution history.
- Assets reads the configured new Warehouse Elasticsearch endpoint directly in production; Query API is diagnostic only.
- Workspace may keep local workflow state and user indexes; it must not treat Warehouse Evidence as a public release without Assets review.
- Warehouse never falls back to the legacy `warehouse` release, `astro_*` indices, or the frozen legacy checkout.
- SourceUnit is not present in any of these v1 contracts.

### MOC Core conformance

`MOC-Core-SDK/fixtures/conformance/healpix-v1.json` is the shared numerical
fixture for ICRS to NESTED `order/ipix` conversion and the four precision
labels. Warehouse copies the reviewed fixture into
`spatial-core/src/test/resources/conformance/healpix-v1.json` and executes every
vector in its Java test suite. The source commit and fixture digest are recorded
in [`contracts/conformance/moc-core-source.json`](../contracts/conformance/moc-core-source.json).
Update the copied fixture only alongside the Core commit recorded in the
release provenance; a changed vector is a cross-repository contract change and
must be reviewed by both consumers.

## End-To-End Workflows

### User remote scan

Workspace or Assets submits a namespaced `ScanRequest`. Warehouse validates the
embedded ScanPlan, creates a Job in that same namespace, writes current state to
Elasticsearch, and stores inventory/errors in Evidence. The caller polls status
and may continue other work while the Job runs. Scanner and MOC Jobs do not
replay after failure. Extraction errors are terminal:
the scanner stops at the first bad file/row, does not skip ahead, and the Job has
`backoffLimit=0`. A retry is a new request/execution identity after the caller
reviews Evidence; only bounded transport retries occur inside the S3 and
Elasticsearch adapters.

### Public MOC discovery

Assets submits a bounded `MocDiscoveryRequest`. Warehouse queries only the fixed
allowlisted policy and stores the response/evidence. Assets then independently
reviews the source and publishes a MOC or release artifact. Discovery evidence
never becomes an `ast_*` layer automatically.

### Public release consumption

Assets publishes a verified catalog/MOC/Resource Package. Workspace consumes the
published package for user-facing work. Warehouse remains the source of current
file-level evidence and reverse lookup, not the public presentation layer.
