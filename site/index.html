Three projects, clear ownership

Warehouse

Validates and executes scans, extracts file-level coverage, refreshes current indices, and retains inventory and extraction evidence. The Operator translates intent into namespaced Jobs.

Assets

Owns the public catalog, reviewed MOCs, releases, evidence presentation, overlap and reverse-lookup UX. Production reads the configured new Warehouse Elasticsearch directly.

Workspace

Owns user assets, connectors, labels, and local workflows. It can submit remote ScanRequests in an explicitly allowlisted namespace.

Warehouse is not a workflow engine, universal catalog, reduction system, or download proxy. Evidence-only MOC discovery does not publish public geometry or write ast_* documents. SourceUnit is reserved, not implemented.

02 / Extraction

Declare meaning, not processing steps

A ScanPlan declares exactly one ExtractionMode for one source and one CoverageLayer. The scanner owns internal step ordering and validates the entire plan before enumeration or credentialed I/O.

fits-wcs

Image and cube footprints

Reads supported WCS headers and rasterizes at the required outputOrder. Sampled coverage is estimated; there is no silent center-point fallback.

fits-header-position

Header position evidence

Maps an explicit FITS header position at the required outputOrder. Precision is entrypoint-only, not an instrument footprint.

catalog-radec

Catalog occupancy

Reads configured RA and Dec columns in ICRS degrees and maps them to NESTED cells at outputOrder. Coverage describes file occupancy, not a per-row object index.

catalog-healpix

Explicit source cells

Requires a pixel column and exactly one fixed source order or order column. Preserves explicit NESTED order/ipix; an absent source order is never assumed to be 8.

Local, S3-compatible, and OSS sources

The local connector accepts a directory or single file. S3-compatible and OSS endpoints use the AWS SDK adapter, with canonical s3://bucket/key or oss://bucket/key identities. Supply a signing region when required. Credential references point to environment variables or mounted files; never put credential values in a plan.

Metadata only. FITS extraction reads headers, and catalogs expose configured spatial columns. Warehouse never reads or copies scientific image, spectrum, or cube arrays. Unsupported formats remain discovered FileAssets with evidence and no invented coverage.

Declare modality explicitly: image, spectrum, cube, catalog, timeseries, visibility, event, or other.

03 / Submission

From local diagnostic to persisted scan

Start with a bounded catalog and a complete ScanPlan v2. The example below expects CSV or TSV files with ra and dec columns under /data.

1. Inspect a local catalog

This is a complete scan-plan.json. Adapt the source and evidence paths to your machine. The sink remains declared even when --memory bypasses Elasticsearch.

scan-plan.json / ScanPlan v2
{
  "version": 2,
  "scanRunId": "local-catalog-example",
  "layer": {
    "layerId": "local-catalog-example",
    "surveyId": "example",
    "releaseId": "local",
    "productId": "catalog",
    "modality": "catalog",
    "coverageRole": "occupancy"
  },
  "source": {
    "connector": {"type": "local"},
    "location": {"rootPath": "/data"}
  },
  "filters": {"includeSuffixes": [".csv", ".tsv"]},
  "extraction": {
    "mode": "catalog-radec",
    "outputOrder": 8,
    "catalog": {"raColumn": "ra", "decColumn": "dec"}
  },
  "sink": {
    "connector": {
      "type": "elasticsearch",
      "endpoint": "http://localhost:9200",
      "credentialRef": {}
    }
  },
  "evidence": {
    "outputPath": "/var/lib/atlas-evidence/local-catalog-example"
  }
}
Local CLI / from the repository root
mvn -B package
java -jar scanner-cli/target/scanner-cli-0.1.0-SNAPSHOT-runner.jar \
  --plan /path/to/scan-plan.json --memory

Memory diagnostics do not persist searchable state. Evidence is optional only with --memory; if declared, use a writable output path. To persist, omit --memory, configure the new Warehouse Elasticsearch endpoint and credential references, provision the strict indices, and retain evidence. Scanner startup does not create or recreate indices.

2. Submit a namespaced ScanRequest

This complete request wraps the same local catalog intent for Kubernetes. Install infrastructure and the Operator with the supported Helm charts first. Provision the evidence PVC and a Bound source PVC labelled atlas.zhejianglab.org/scanner-source=true in atlas-warehouse. The source claim's catalogs subdirectory is mounted read-only at /data.

scanrequest-local.example.yaml
apiVersion: atlas.zhejianglab.org/v1alpha1
kind: ScanRequest
metadata:
  name: local-catalog-example
  namespace: atlas-warehouse
spec:
  scanner:
    image: ghcr.io/astro-survey-atlas/astro-atlas-scanner:0.1.0
    backoffLimit: 0
    activeDeadlineSeconds: 3600
    evidence:
      claimName: atlas-evidence
      mountPath: /var/lib/atlas-evidence
    sourceVolume:
      claimName: atlas-source-catalogs
      mountPath: /data
      subPath: catalogs
  plan:
    version: 2
    scanRunId: local-catalog-example
    layer:
      layerId: local-catalog-example
      surveyId: example
      releaseId: local
      productId: catalog
      modality: catalog
      coverageRole: occupancy
    source:
      connector:
        type: local
      location:
        rootPath: /data
    filters:
      includeSuffixes: [.csv, .tsv]
    extraction:
      mode: catalog-radec
      outputOrder: 8
      catalog:
        raColumn: ra
        decColumn: dec
    sink:
      connector:
        type: elasticsearch
        endpoint: http://atlas-warehouse-elasticsearch:9200
        credentialRef: {}
    evidence:
      outputPath: /var/lib/atlas-evidence/local-catalog-example

The endpoint and image are example deployment settings, not universal defaults. This request assumes a sink without authentication; authenticated deployments must add namespace-local Secret bindings and plan credential references. Source paths must stay inside the declared source mount, and evidence paths inside the evidence mount. Host paths and cross-namespace claims are not supported.

Upstream examples: complete local request, OSS request with Secret references, and Helm installation.

3. Observe execution and evidence

Submit and monitor / configured cluster required
kubectl apply -f deploy/kubernetes/scanrequest-local.example.yaml
kubectl -n atlas-warehouse get scanrequest local-catalog-example -w

# In another terminal, inspect status and the reported Job name.
kubectl -n atlas-warehouse get scanrequest local-catalog-example -o yaml
JOB_NAME=$(kubectl -n atlas-warehouse get scanrequest local-catalog-example \
  -o jsonpath='{.status.jobName}')
kubectl -n atlas-warehouse logs "job/${JOB_NAME}" --follow

Wait for a Job name before requesting logs. Request phases are INVALID, WAITING, SUBMITTED, RUNNING, SUCCEEDED, and FAILED. The summary reports counts, available orders, source snapshot hash, errors, and evidence path. Detailed inventory, normalized scan, provenance, and errors stay on the evidence volume, not in the browser's initial request.

The Operator creates or adopts an immutable plan ConfigMap and execution-hash-named Job. All resources and credential references remain in the request namespace. The default allowlist watches only atlas-warehouse; Workspace submissions in astro-data-workspace require explicit opt-in. An empty allowlist fails closed.

04 / Reverse lookup

Ask for cells. Receive file candidates.

The Query API is read-only and diagnostic, not a scan submission endpoint or a required production hop. Assets performs this lookup directly against its configured Warehouse Elasticsearch.

GET /v2/files/healpix
# Point this at your separately running diagnostic Query API.
QUERY_API=http://localhost:8080
curl --fail-with-body --get "$QUERY_API/v2/files/healpix" \
  --data-urlencode 'layers=local-catalog-example' \
  --data-urlencode 'order=8' \
  --data-urlencode 'pixels=123' \
  --data-urlencode 'limit=100'

Replace pixel 123 with a cell from your scan evidence. Supply comma-separated layers and pixels, and one explicit order. Every requested layer must be ACTIVE and support that order. Results contain unique files and their matchingCoverage; they are cell-intersection candidates, not exact geometric overlap claims.

The default limit is 100, maximum 1000. A response or edge limit sets truncated=true. When nextCursor is non-null, pass it as the opaque cursor with the same normalized layers, order, and pixels. Do not treat truncation as a precision value or assume every truncated response has another page.

05 / Storage contract

Three indices. One current state.

Strict mappings separate layer lifecycle, global file identity, and layer-scoped spatial associations. The v1 suffix versions mappings, not scan runs. Legacy astro_* indices are untouched and never used as fallback.

CoverageLayer

ast_layer_index_v1 holds survey/release/product identity, modality, role, entrypoint, state, lease, snapshot hash, available orders, counts, and errors. Document ID: layer_id.

FileAsset

ast_file_index_v1 holds canonical URI, name/type, parent URI, size, and timestamps. Document ID: SHA-256 of the canonical source URI. No raw data, modality, or layer-owned coverage list.

SpatialCoverage

ast_coverage_index_v1 associates a layer and file with an explicit cell, method, role, modality, and precision. Identity is deterministic over layer, file, order, cell, and role.

The offline explorer displays mapping fields and illustrative documents. Read the canonical templates for the authoritative field definitions.

06 / Invariants

Precision is not completeness

Coverage always retains its actual ICRS, NESTED HEALPix order/ipix. Coarsening finer data is allowed; expanding coarse coverage into claimed finer precision is not.

exact

Exact cell assignment for the represented input, such as catalog occupancy. It does not turn a cell intersection into an exact geometry claim.

estimated

Approximate coverage, including sampled WCS rasterization. Preserve that qualification in reverse-lookup results.

entrypoint-only

Limited positional or entrypoint evidence, not a full footprint. If only an official URL is known, Assets reads the layer entrypoint; no synthetic file or coverage edge is created.

Refresh a layer, not a historical index generation

UPDATING

An expiring lease prevents overlapping refreshes. Old layer coverage is deleted before replacement; the layer is unavailable during the update, never silently empty.

ACTIVE

Only verified successful current state is searchable. A successful empty scan is ACTIVE with zero coverage, a valid empty result.

FAILED

Partial or failed work is unavailable. Any physical partial edges remain hidden behind the state gate; old coverage is not served as a fallback.

Failure is terminal for an execution. The first extraction error, including a malformed catalog row, stops the scan and is retained as evidence. Later input is not enumerated. Jobs use backoffLimit=0; diagnose and submit a new request/execution identity to retry. Only bounded transport retries remain. Suffix filtering, blank lines, and comments are not failures.

A SourceSnapshot retains the named inventory and SHA-256 identity with enumeration and extraction errors. Evidence lives outside the online indices and browser startup data. Job TTL is operational cleanup, not public scan history. Credentials never belong in plan values, evidence documents, logs, indices, or query responses.
